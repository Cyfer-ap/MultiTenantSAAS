# Multi-Tenant SaaS Platform — Current Implementation Plan

This file is the active implementation roadmap for the Spring Boot project.

## 1. Project goal

Build a production-style multi-tenant SaaS backend where:

```text
Multiple organizations use one application
Every organization is a tenant
Tenant-owned data is isolated
Tenant users have controlled roles
Platform administrators are separate from tenant users
Authentication and authorization are DB-backed
Business operations are auditable
The backend exposes a stable API for a future frontend
```

The current business vertical is project management:

```text
Tenants
Users
Invitations
Projects
Project members
Tasks
Dashboards
Audit logs
```

## 4. Main implementation decisions

```text
Tenant onboarding creates tenant + initial admin
Direct tenant creation endpoint is disabled
System admins are separate from APP_USERS
Tenant roles are fixed for the MVP
Project roles are separate from tenant roles
Refresh tokens are stored as hashes
Invitation/reset tokens are stored as hashes
Soft deletion is represented by status
Authorization rechecks live database state
Errors use stable machine-readable error codes
Environment secrets are externalized
Schema changes use Flyway
```

## 12. Current Flyway recovery

Problem:

```text
V6 was applied when the file was empty.
The database stored checksum 0.
SQL was then added to V6.
Flyway rejected the changed checksum.
```

Required recovery:

```text
V6__expand_tenant_audit_actions.sql
- keep as a zero-byte file

V7__convert_audit_action_to_varchar.sql
- contains the real schema change
```

V7 SQL:

```sql
ALTER TABLE audit_logs
    ALTER COLUMN action SET DATA TYPE VARCHAR(60);

ALTER TABLE audit_logs
    ALTER COLUMN action SET NOT NULL;
```

After the recovery:

```text
Start application
Verify Flyway history
Run all tests
Verify audit filters through Postman
```
